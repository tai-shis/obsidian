### Review
**Program**: A list of instructions
**Process**: A program in execution
### Kernel Purposes
**Manages System Resources**
- Time:
	- CPU time
	- device interface access
- Space
	- main memory space
	- secondary storage spacee
- Power
	- important recently (due to mobile systems, and usage concerns)
**Allocates System Resources**
- To processes (providing per-process runtime environments)
- To itself
	- the kernel is a process too (with heightened privleges)
- Provides a set of common services to processes
	- ie. system call library abstraction
- Provides controls and protection
	- services supporting shared resources and process cooperation
	- orchestrates control of processes
- Provides a user environment - what are we interacting with?
	- You are interacting with an interface which performs actions (interacting with the operating system) for you.
	- As well as physically interacting with the hardware.
The kernel provides a **per-process runtime environment**
- this is what we call the context
- each process runs in its *own* address space
- each process thinks/acts that it has the CPU exclusively
	- doesn't know that there are resources being allocated elsewhere
- each process makes periodic service requests t the kernel
	- e.g. I/O operations, process management (creation/termination)
- The shell and the "some program" processes are isolated from others
	- the shell tells the operating system - when this program i'm running is done executing - bring the control back to me
